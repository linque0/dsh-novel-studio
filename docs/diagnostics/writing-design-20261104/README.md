## 宿主加载与已知边界

插件在 `src/index.js` 启动时逐文件注册精确静态路由。重建后 HTML 引用新的哈希文件，**仅重载 iframe 并不能为新哈希补注册路由**，可能造成 HTML/健康检查为 200 而正文白屏。本次已在实际 DSH 侧栏观察到这种白屏；这修正了此前“刷新即可，不需要重载插件”的判断。

**已修**（同一仓库的后续会话）：静态产物不再逐文件注册，改由 webServer 前缀路由承接 `/api/novelstudio/app`
（按请求实时读盘），重建 `assets/app` 后点「重新载入」即可，不需要重启 DSH；宿主没有 webServer 时回落到逐文件
精确路由，面板顶栏会显示「需重启」。判据在 `scripts/host-contract.mjs`（精确/前缀双模式 + 前缀被占时回落）与
`scripts/smoke.mjs`（服务器启动后新增的产物文件仍 200）。边界不变：插件服务端代码（`src/*.js`）与面板代码
（`lib/client.js`）仍需重载插件或重启一次。实际宿主加载结果确认后应更新此节，不把本地截图冒充线上验收。

样式不会替用户设定章节字数目标：已有目标显示当前/目标与进度，未设置仍显示实际字数。此状态差异不通过伪造 3000 字目标掩盖。

本轮宿主操作记录：界面输入保护连续检测到人工输入，自动点击被中止，已询问可用的窗口交接时段。随后改用配置热重载：为 `novel-studio` 临时加入 `disabled:true`，3 秒后恢复 profile 原始字节，恢复结果经 SHA-256 比较确认。实际 DSH 窗口最终加载/视觉核验仍待交接；本地 209 项通过和本目录截图均不等同于这一步已经完成。
