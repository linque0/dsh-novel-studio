# 插件版「隐现」作为桌面版第五套皮肤：接入设计草案

日期：2026-11-07。状态：供审阅的建议方案；未进入实施。

## 1. 目标与范围

将插件版**当前实际使用的整套前端**接入桌面版小说工坊，成为设置中可选择、可退出、可持久化的「隐现」皮肤。覆盖书架、正文、大纲、设定、人物、灵感、设置、写作数据、全局弹层和独立窗口，不能只接书架或替换配色。

建议默认：保留桌面版现有 original / gravity / glaze / crimson 四套皮肤及当前用户选择；新增皮肤内部 ID 使用 `dsh`，显示名使用「隐现」。沿用 ID 是为了复用已有大量 `body[data-skin='dsh']` 规则，ID 不代表运行于 DSH。

建议默认：新皮肤继续使用桌面版作品库、Electron、恍然梦、创作台、预设、文件读写、备份恢复、编辑锁和跨窗口通信。插件界面里因 DSH 接管而隐藏的桌面能力，应在新皮肤中提供适配后的入口。这些是本方案的建议，不是用户已经逐项确认的决定。

本次交付仅为设计和实施计划。不写产品代码、不安装依赖、不构建覆盖产物、不更改真实作品库、不提交现有工作区改动。

## 3. 可选路径与推荐

| 路径 | 代价与结果 | 判断 |
|---|---|---|
| 只搬 CSS、只开放 dsh 选择项 | 初始修改少，但人物/设定/设置/分析的 DOM 与状态都不匹配 | 不满足完整前端要求 |
| 在桌面内嵌插件构建产物或第二个完整 SPA | 可以较快显示插件外观，但产生第二套启动、状态、数据库与桥接边界，编辑权与 AI 很难统一 | 不建议作为正式接入 |
| 在桌面现有应用中增加皮肤视图，复用桌面服务 | 逐模块适配工作较多，可维持同一作品库、编辑器、原生能力与四套旧皮肤 | **推荐，以下计划按此编写** |

本次先提供可审阅的完整草案；推荐路径尚未被标为用户已选择。无需在计划交付前停止到空泛的路径询问，正式实施仍待用户下一步指示。

## 4. 架构边界

### 4.1 外观、宿主、功能能力分别判断

- `__NS_PLUGIN__` 继续表示构建宿主；桌面始终为 false。
- `isLatentSkin(ui.skin)` 只判断是否使用隐现外观；布局、流动背景、新面板矩阵由它决定。
- Electron 能力由桌面现有桥接和能力检测决定。不能因皮肤变成 dsh，就设置 `window.__NS_AGENT__='dsh'` 或加载 iframe shim。
- 桌面库名保持 `novel-studio`，数据位置和库同步路径保持桌面原有行为。
- 保留 `visibleSkins(audience)` / `visibleSkinsForBuild()` / `normalizeSkin()` / `resolveSkin()` 原有公开函数。dsh 元数据支持 desktop 与 plugin 两种受众；未知值和未知 surface 仍回落 original。
- `isStudioSkin()` 保持原来三套艺术皮肤的意义，不把隐现机械加入，避免触发错误的 Teleport 目标或旧艺术布局。

### 4.2 新视图隔离，数据与编辑器共用

目标新增 `src/components/skins/latent/`，承载插件新视图。独立的设定、人物、大纲、设置和分析组件放在该目录各自的子目录；插件覆盖过桌面同名文件时，迁入局部副本并修正 import，避免改坏旧皮肤。

书架在已有 Bookshelf 控制器上加 LatentShelf 分支。工作台新增 LatentWorkbench **布局壳**，通过 slots 和事件接入原有导航、目录、中心模块、批注和 AI。业务操作仍由现有 work/ui/store 和父控制器负责。

正文继续使用 `StudioWorkspace.vue` 管理的同一 EditorPane、StoryEditor 和 Teleport，不复制 Tiptap 编辑会话，不用 `:key="skin"` 重建整个应用。切换 Workbench 的布局壳时保留 `#writing-editor-host` 等 Teleport 宿主的 DOM 身份；不能先卸载旧宿主再指望同名新节点自动接管。皮肤变化不能中断输入法、清空撤销栈、丢失未保存输入或释放实体锁。

既有 CharacterCenter、MubuView、OutlineCenter、SettingsWindow、StatsModal 等保留旧皮肤路径。共享服务的必要修复合并一次，不能形成“换皮肤就换保存算法”的分叉。

### 4.3 样式与主题

新增 `src/styles/skins/latent/index.css`，按插件当前有效顺序引入基础 dsh、language、flow-shell、outline-fusion、characters-fusion、settings-fusion；同时核对 latent-shelf/studio、chars-*、lore-free-tree、writing-stats 两层样式。

所有新规则必须约束于隐现皮肤或唯一组件根。逐项检查 `.pane`、`.icon`、`.workspace`、`dialog`、`html.writing-analysis-open`、teleport 弹层和 scoped 样式，不能靠加载顺序让其他皮肤被动改变。不要全局强制 data-skin。

桌面新增主题适配：`ui.theme='night'` 为暗，其余现有主题为亮；保留原 theme 值，退出隐现后仍恢复对应旧皮肤表现。书架和插件原本固定暗色的艺术面保持现状，跟随主题的编辑面/通用浮层同步亮暗。

主题适配写入桌面文档本身需要的 `--ns-*`、`data-ns-dark` 和通知，复用插件 theme 覆盖。**浅色删除 `data-ns-dark` 属性**，不能写 `'0'`：现有 CSS 用属性存在性，而 theme.js 用值判断，否则两者会一暗一亮。退出隐现后删除本适配器拥有的变量、属性、监听和背景引擎。桌面不得写 `data-ns-host='dsh'`；当前 CSS 中依赖该属性的规则要判断是外观需求还是宿主规则，前者移至皮肤作用域，后者不迁。

### 4.4 数据兼容

- 仅切肤可写 `appconfig.skin`，不改作品表、不触发默认设定补种、不自动调整图谱坐标或内容结构。
- 保留桌面 `charGraph:<workId>` 的平铺坐标；新相机状态写 `latent:charCamera:<workId>`。新增 `loadCharCamera` / `saveCharCamera` 供新图谱调用，参数沿用 `scope:layout` 和 `{x,y,z}`。如读到已包装图谱文档，兼容读取 positions，但不在首次显示时回写。人物几何按 skin 分支处理，旧投影和逆投影不变。
- 设定补入 heading/kind 等可选字段，旧节点缺字段时只在展示层默认。新建/移动/删除/撤销沿用记录 ID 和完整字段，不丢自定义字段。已有作品的默认根节点只允许用户主动补齐。
- 新视图偏好和 per-work 状态使用明确命名空间；仅在 UI 边界转换为插件组件所需字段，避免新旧设定详情、筛选、滚动互相覆盖。
- 写作统计统一计量：正文、日志、必要 AI 记忆任务在同一事务提交；失败都回滚，重试不重复加日志；停用旧 beforePut 统计钩子，保留 autosave.error 原有可读错误信息契约。字数差值计算独立放在 `services/writing-word-delta.js`，保存链路不反向依赖完整分析模型。
- 版本快照可增添可选 `fmt` 字段；旧记录读时兼容，不批量改写历史，不补造过去的每日写作量。
- 写作分析历史仍是本地读模型，不因引入 UI 而把 revisions/wordlog 加到作品源表同步协议。
- 不增加数据库 schema 版本，除非实施时证明现有表/索引不足；若发生此变化，先更新计划和回退约束。

## 6. 切换和生命周期

切肤由 `ui.setSkin()` 单一写入口完成。先序列化选择请求和处理编辑焦点；正文编辑器持续挂载，contenteditable 设定/人物编辑先提交局部草稿。无法保存局部草稿时取消本次切换并保留原界面。皮肤偏好落库成功后才应用；快速连续选择按顺序或禁用控件处理，旧请求不能覆盖最后一次选择。

跨窗口仍走 prefs-changed。已打开的主窗、设置窗、内容窗、AI 窗应同步外观，但不重新抢编辑权，不改变选中作品/章节。现有 appbus→loadPrefs 会直接写 skin，必须改为经过同一切换协调器，不能只防护 SkinPicker。

窗口接收远端变化时重读数据库中最后成功写入的 skin，不信任可能乱序的事件载荷；等待本窗口 compositionend 和局部草稿提交后应用。若本窗口提交失败，**仅该窗口暂时保留旧外观**并显示可重试的“外观更新待完成”状态，记录最新待应用值，不把旧 skin 反写全局偏好；恢复保存后重新读最新值再应用。其他普通偏好可继续更新。快速收到多个切换时只应用最新数据库值，避免各窗回写形成循环。启动首次载入无需保存屏障，仍需等主题就绪。

新窗等待偏好与主题就绪再显示；设置继续遵守 panelReady。

打开设置失败时允许就地回退，但要保留工作区挂载和返回位置；不能因为切到 ui.view=settings 销毁当前正文编辑器。根组件将就地 settings 视图映射到 work 皮肤 surface，再调用 resolveSkin；否则注册表对未知 surface 的正确回落会意外把设置页切成 original。

流动背景只在隐现视图激活时创建；切回旧皮肤、销毁窗口、隐藏不需要的视图时暂停/销毁。沿用 WebGL2、context loss→CPU、新 canvas 兜底、reduced motion；不得同时运行四套旧皮肤背景和隐现背景。

## 7. 验收与发布约束

1. 完整性：上表各模块均有真实入口，所有主要按钮能完成桌面原动作。
2. 保真：以插件在 DSH 宿主中的当前构建实渲染为基线，记录宿主亮暗、字号及实际 --ns-* 计算令牌，比较 1440/1280/1080 与适用窄档的真实数据、同字体、同主题截图。裸 app 构建缺少 shim/宿主令牌，不能单独充当现状基线；离线复现须注入已记录的令牌快照。桌面 AI/皮肤控件新增区域单独标注，不把现有原型当发布基线。
3. 数据：切肤前后源表逐表数量与规范化内容哈希一致；主动编辑和时间戳变化单独核验，不能用关闭保存来“确保一致”。恢复/重启/同步后的新增可选字段仍保留。
4. 互切：四个旧皮肤与隐现双向切换，含未保存正文、设定 IME 输入、图谱拖动、弹层打开和多窗口场景。
5. 窗口：1080px 主窗、800px 内容面板、1000px 默认设置窗，以及允许的 380px AI 窗；380/560/760 的浏览器布局检查为补充，不更改桌面最小宽度。
6. 失败：偏好写失败、保存失败、备份取消、GPU 不可用、上下文丢失、快速跨作品/跨皮肤切换都有确定行为。
7. 旧皮肤：原有设置、纸面、图谱坐标、艺术背景、AI 与拆窗均通过对应回归，不能只验收新增第五套。
8. 运行与发布：验证 Vite 开发模式和打包后 app://，核查离线字体/图片/chunk 加载。安装包仅在功能与视觉验收通过后生成。

首次发布保留用户原皮肤；不自动改为隐现。紧急停用通过注册表禁用新皮肤并回落 original；不回滚用户正文、不删除旧资源、不降数据库版本。开发变更按模块独立提交，回退仅针对本次提交，不能 reset 两个已有脏工作树。

## 8. 进入实施前的基线

推荐方案按“整套外观加入、桌面能力保留、旧皮肤保留、不导入插件作品数据、不做双仓自动双向同步”制定。若用户要同步替换桌面旧界面、把 DSH Agent 接进桌面或默认切换所有用户，均属于范围变化，另行改方案。

配套实施计划：`../plans/2026-11-07-latent-desktop-skin.md`。可以由实施者自行决定局部组件拆分和必要的命名微调；不能自行改变皮肤 ID、数据兼容策略、编辑器单实例、桌面能力保留和验收范围。
