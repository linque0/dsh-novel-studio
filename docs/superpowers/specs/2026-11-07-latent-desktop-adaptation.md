# 「隐现」桌面能力与前端适配补充规格

日期：2026-11-07。状态：计划修订，未实施。本文为接入设计和实施计划的组成部分。

用户已明确要求：桌面版的拆窗、恍然梦入口和更多设置项必须做相应前端界面适配。这三项是接入必做范围，不能仅保留底层 API，也不能照搬插件界面隐藏它们。

## 1. 版本边界与代码依据

| 能力 | 插件现状 | 桌面接入要求 | 主要代码依据（桌面仓库相对路径） |
|---|---|---|---|
| 应用外壳 | DSH 内嵌页面、胶囊模块导航 | 增加桌面动作区域、独立窗口外壳 | AppTopbar、Workbench、PanelHost |
| 拆窗 | shim/宿主能力受限，不能以有组件路径代表真实支持 | 正文/大纲/人物/设定/灵感/AI 的真实拆出、聚焦、锁提示与关闭 | `services/panelwindows.js`、`electron/panels.js` |
| 恍然梦 | 插件由 DSH 接管，相关桌面入口被过滤 | 书架入梦、工作台双模式、模块助手、选区发送和独立 AI/创作台/预设 | `agent/DreamModeEntries.vue`、`services/ai/entry-modes.js`、`ai/AiAssistantPanel.vue` |
| 设置 | appearance/data/about 三页 | appearance/ai/knowledge/data/about 五页及所有原动作 | `components/SettingsWindow.vue:PAGES` |
| 原生数据 | 依赖宿主文件与导入桥 | 原生保存/目录选择、迁移重启、旧位置管理 | SettingsWindow、`services/fileio.js` |

本补充以用户已声明的桌面能力为准。插件源码中残留 panelOpen 或恍然梦组件，不等于本轮可以直接采用插件宿主的能力策略。

已发现需要具体改写的来源规则：`app/plugin/dsh/dsh.css` 约 760–763 行以 `body[data-skin='dsh'] .module-agent{display:none;}` 隐藏所有模块助手。目标桌面迁入样式时须移除此隐藏规则或明确限制到插件宿主，不能仅修正组件的 v-if；各模块助手须验证真实可见且可点击。源插件文件本身保持不动。

## 2. 桌面顶栏与入口布局

外观继续使用隐现的流动背景、玻璃面板和胶囊样式；桌面动作有专用位置，不与模块导航混成一条不断增长的按钮行。

| 页面/窗口 | 顶部主要结构 | 必须直接可发现的动作 | 溢出处理 |
|---|---|---|---|
| 主窗书架 | 品牌与新书入口 / 模块导航 / 桌面动作 | 「恍然梦-入梦」、设置、写作数据 | 无当前作品不显示假“浅眠”；普通模块按当前聚焦作品处理 |
| 主窗正文/人物/设定/灵感 | 当前作品与模块导航 / 状态 / 桌面动作 | 「恍然梦-入梦」「恍然梦-浅眠」、本模块「独立窗口」、更多 | 控制区放不下时，桌面动作降至一条紧凑模块工具行；不靠横向滚动藏 AI/拆窗 |
| 主窗大纲 | 大纲专用胶囊导航 / 模块动作行 | 同样提供双模式与独立窗口；画布操作和应用设置分别标识 | 不能因采用 OutlineTopbar 漏掉桌面动作，应用设置不能仍只标“设置”而与画布设置混淆 |
| 内容独立窗 | 作品名 / 模块与实体名 / 保存状态 / 窗口动作 | 「保存并关闭」、聚焦主窗口、相应模块助手 | 复用当前窗口不再提供“再拆出自身”；800px 时次要动作进更多，关闭与错误状态保持可见 |
| AI 独立窗 | 作品范围 / 恍然梦 / 窗口动作 | 模型/预设/功能调整、入梦工作台入口 | 380px 下沿用窄版控件，长模型名截断但提供完整提示；不套三列创作模块壳 |
| 设置独立窗 | 「设置」标题 / 搜索 / 关闭 | 五类设置导航、返回来处能力 | 无框拖动区域与按钮 no-drag 分开，不渲染无意义的作品模块导航 |
| 创作台/预设窗 | 保留自身业务工具区与编辑流程 | 返回写作/故事现场、预设保存/导入导出等当前动作 | 统一隐现字体、边框、玻璃与弹层，不把复杂业务降为只改 root token |

布局根据**容器实际可用宽度**测量，不只依据 outerWidth。主窗 1080px 已需验收完整桌面动作；不能把“在 1440px 显示得下”当通过。次要操作有更多菜单兜底，但菜单分组固定为“本模块”“窗口”“写作工具”“应用”，模块导航仍有自己的独立路径。

建议新增 `LatentDesktopActions.vue` 统一主窗和大纲的桌面动作，并由 `LatentPanelTopbar.vue` 处理独立窗口动作。动作生成集中在 `services/latent/desktop-actions.js`，业务 handler 继续调用已有服务。禁用项必须有理由：未打开作品、操作确需实体但尚未选择、保存/移交中、编辑权在别窗、当前能力不可用。原来允许空模块窗口的动作不增加无依据的禁用条件。

## 3. 拆窗的界面与状态契约

### 3.1 各模块拆出范围

| 类型 | entityId | 主窗或来源窗表现 | 新窗口内容 |
|---|---|---|---|
| chapter | 当前选中章节 ID；无章节时不新增强制禁用，沿用现有空窗口行为 | 对已被锁章节只读，并提供「前往窗口」 | 同一正文编辑与目录/批注；章选变化走 panelSetEntity |
| outline | 空字符串，整模块 | 展示大纲已拆出提示，入口转为「前往窗口」 | 新隐现大纲画布/文本、结构与详情 |
| lore | 空字符串，整模块 | 新隐现设定壳整体尊重模块锁 | 三视图、树、引用、富文本与面板矩阵 |
| characters | 当前人物 ID，空值遵循原模块锁语义 | 当前被锁人物不可编辑，其他人物按既有规则可选 | 名录、卷宗、上下文、图谱；切换人物走锁迁移 |
| snippets | 当前灵感 ID，空值遵循原模块锁语义 | 当前被锁条目只读或显示占位 | 列表、详情、标签；切换条目走锁迁移 |
| ai | 空字符串，当前作品 AI | 隐藏主窗停靠列，「浅眠」聚焦已拆窗，不新建第二会话 | 完整 AiAssistantPanel |
| agent | 既有 agent 锁规则，不自行另造 | 与正文编辑权冲突时显示可理解提示 | 同一 StudioWorkspace/故事创作台 |
| settings / ai-presets | 设置与预设各自原有范围 | 不制造正文只读占位 | 设置五页 / 预设自身编辑界面 |

拆窗动作仍由 `popOut/isPopped/focusPopped/panelSetEntity` 和原生锁仲裁负责；新 UI 只呈现状态。原有空实体行为以真实服务返回为准，不擅自禁用过去可打开的功能。

### 3.2 状态与交互

- 未拆出：按钮文案「独立窗口」，当前模块在工具行有直接入口，更多→窗口列出可拆类型。
- 正在保存/移交：同一按钮显示忙碌并禁用，防止双击；失败留在原界面，展示原因及重试，不显示成功占位。
- 已拆出：按钮改为「前往窗口」；主窗占位明确作品/模块/实体，提供聚焦动作。不能只变成灰色死按钮。
- 已存在窗口：恢复最小化并聚焦，不复制实例。
- 保存并关闭：先提交本地草稿与 autosave，成功才关闭并释放锁；失败留窗，提示重试。核对当前 PanelHost 非 original 分支 finally-close 路径，不能原样继承导致失败仍关闭。
- 普通关闭键与系统关闭走现有保存拦截协议，不另设绕过保存的“强制关闭”按钮。
- 关闭成功：原窗口解除占位，原选择/筛选/滚动/相机保持合理连续性，不凭空重置模块。

**独立窗的类型、URL 与原生锁身份必须一致。** 来源插件 PanelHost 的 outlineNavigate 会仅改本地 spec.type 和 work.tab；不能复制这个做法。在桌面内容窗里跨模块导航时，通过原生服务打开/聚焦目标模块窗口，或先聚焦主窗再导航，不在仍持有大纲锁的窗口内直接变成可编辑设定页。

「聚焦主窗口」建议作为最小原生补充能力提供 `panelFocusMain():Promise<{ok:boolean}>`，由 preload 暴露并由 panels.js 只聚焦实际主窗；它不代表关闭/合并当前面板。用户需要恢复主窗可写时使用保存并关闭，文案不把二者混称“收回”。

## 4. 恍然梦前端适配

### 4.1 模式与入口

| 入口 | 行为与上下文 | UI 状态 |
|---|---|---|
| 书架「恍然梦-入梦」 | 打开既有 DreamLaunchDialog，选择/创建/打开故事；不能未经选择使用书架最近作品 | 无作品仍可进入；不显示不可用的浅眠 |
| 工作台「入梦」 | 走 enterDreamMode，先保存，进入同一作品的 AgentWorkbench | 高亮入梦；保留正文编辑会话及共同工作稿/正式正文视图 |
| 工作台「浅眠」 | 走 enterLightSleepMode，返回写作视图，打开/收起 AI 停靠列；若已拆出则聚焦 | 反映停靠打开/关闭/已拆出状态，不等同入梦 |
| 正文/大纲/设定/人物/灵感模块助手 | 沿用 TaskLauncher，携带当前作品、模块、选中实体与合法选区 | 模块助手和聊天模式入口分开，避免点助手却切整套工作台 |
| 正文工具栏/右键「发送给恍然梦」 | 保留真实选区和章节锚点，走桌面现有分发与确认 | 不沿用插件的“发送给 DSH”文案或宿主聊天桥 |
| AI 未配置提示 | 打开设置 ai 页，定位连接/模型相关控件 | 新窗首次打开与已存在设置窗均能直达，不能每次落回外观页 |
| AI 参数区 | 保留供应商/模型、写作预设、功能调整、作品知识、预设对照、阶段模型/Skill/规则范围等既有入口 | 业务仍由原组件负责；重要操作不能被 dsh.css 的隐藏选择器遮住 |

AiAssistantPanel、AgentWorkbench、PresetWindow 等均复用桌面原组件，新增隐现专用 palette/外壳和弹层规则，不复制插件删减版本覆盖它们。标题、输入区、模型/预设选择、错误恢复、流式状态、候选确认、历史详情均纳入视觉和操作检查。

### 4.2 AI 与创作区的宽度预算

浅眠停靠沿用 `ui.aiDrawerWidth` 的 300–640px 及拖拽记忆。目录、中心、批注、AI 同开时测量净宽；扣除各侧栏与分隔后中心可用宽度不足 **520px** 时，AI 以右侧覆盖抽屉显示，不强行把正文压成窄缝。该 520px 为本次建议的桌面适配阈值，实施截图验证后可更新规格。

覆盖抽屉有遮罩、关闭按钮、ESC、焦点进入/返回和背景 inert；开启时不同时弹出另一个资料模态抽屉。临时覆盖不篡改目录/批注的持久开关。关闭只是隐藏 AI，不能销毁对话、停止生成或丢失草稿；切肤也不主动 cancel AI。独立 AI 窗本身全高呈现，不再加一层 AI 抽屉。

## 5. 桌面设置：五类信息架构与完整项映射

继续使用插件设置的玻璃矩阵、搜索、分组行、预览、保存提示和移动抽屉语言，扩成五类。不能把整块旧 SettingsWindow 塞进插件设置主栏形成第二层侧栏和两套标题。

| page key / 类别 | 新界面分组 | 必须保留的项目与动作 |
|---|---|---|
| appearance / 外观与排版 | 工坊外观、正文排版、写作空间 | 五皮肤选择；宣纸/羊皮纸/暗夜书房；正文纸面装帧与预览；中文/西文字体；13–24px 字号；顶栏自动隐藏；恢复默认 |
| ai / 模型设置 | 供应商预设、连接、模型列表、预设参数 | 新建/切换/重命名/复制/删除/启停供应商；Base URL、API 格式、密钥配置/清除、连接测试；拉取/手动添加/移除/启停/选用模型；逐模型配置；温度、隐私模式、自动记忆与既有禁用关系 |
| knowledge / 知识库模型 | 当前连接摘要、语义检索、向量模型 | 继承当前供应商连接；检索开关、模型名；无供应商时前往模型设置；不支持向量接口时解释不可用，保留回落行为 |
| data / 备份与存储 | 导入导出、完整备份、回收站、当前位置、旧位置管理 | 导入、按章节导出、JSON 备份/恢复、回收站；显示完整路径/自定义标记；打开目录；选择新位置迁移并重启；迁回默认位置；是否保留旧位置；列出旧位置大小与打开/清理缓存/删除数据；路径失效回落提示和清除失效记录 |
| about / 帮助与关于 | 写作数据、帮助、应用信息 | 写作速览/分析、手册与快捷键、桌面真实版本及原有关于内容 |

逐模型配置包含已有开关、上下文窗口、最大输出、温度覆盖与备注。供应商连接预设与写作提示词预设是两种业务：写作预设继续进入原 PresetWindow，不与模型设置左侧的供应商预设列表混为一组。

阶段模型、写作 Skill、规则范围、作品知识、写作预设编辑/导入导出、预设对照等原本从 AI 功能区打开的能力，保留这些入口并适配相应弹层/窗口；不把它们无依据地复制为全局设置页。

### 5.1 布局与组件边界

- 外层统一五页侧栏和搜索；宽度不足时切抽屉，不使用插件固定三页的页面枚举、筛选校验和目录长度。
- 页面元数据统一从五页目录生成；替换插件 breadcrumb/footRight 中仅 appearance/data/else-about 的硬编码分支，同时扩展 settingsPage 校验、滚动记忆与检索定位，否则 ai/knowledge 会显示错误面包屑或被载入偏好时丢弃。
- `settings-catalog.js` 覆盖五页所有主要控件和动作，搜索可定位模型/API/密钥/向量/纸面/存储/清理等；搜索索引只包含静态标题与说明，不收集真实密钥、路径或用户数据。
- 模型页复用 AiSettings；只保留其有业务意义的供应商列表，移除重复的全局导航/容器标题。内容容器不足 640px 时供应商选择与详情上下排列，模型列表独立滚动；不设置造成横向溢出的固定最小宽。
- knowledge 页复用 KnowledgeModelSettings，`go-ai` 事件实际切到 ai 页；无预设、不支持协议、连接失败都有明确状态。
- 数据位置提取为共享 `DataLocationSettings.vue`，保留旧 SettingsWindow 的确认框和动作语义；新皮肤重做行、路径、危险动作与进度的布局。长路径可换行或复制/提示完整内容，不能遮住“迁移/取消”。
- 外观预览仅在 appearance 显示；模型、知识库、数据页拿完整主栏宽度，不能继续为预览留出空白第三栏。
- 默认设置窗 1000×700，最小内容窗 800px；五类导航、复杂模型表单、长 URL/路径、确认弹层均在这两档真实 Electron 窗口验收。

### 5.2 设置定向打开

新增统一 `openSettings(ui,{page,settingId}={})`，page 值域为五类，settingId 由静态目录白名单校验。一般齿轮沿用最近分类；“模型设置”显式进入 ai；KnowledgeModelSettings 的 go-ai 和 AI 未就绪提示都走此接口。已有 AI 组件直接 panelOpen 的调用要一并改造。

应用设置窗口统一使用 `{type:'settings',workId:'app',entityId:''}`，作品上下文和页码不作为锁键。`panelOpen` 可附加白名单 `settingsPage/settingId`；新窗将它们编码到启动查询，已有窗用定向 `settings:navigate` 通知定位并聚焦。消息经现有 app:event 接口发送到目标设置窗，不广播导航到所有工作区，不携带密钥。需要在 electron/panels.js 的 spec 归一、复用窗口分支和 URL 构建里显式保留这些字段，否则只是定义前端函数但到不了已有窗口。

初次加载、窗口已开且正在别类、窗口正在加载、就地回退四种情况都要定位正确；跨窗口 prefs-changed 只同步偏好，不擅自切换当前设置分类。AI/模型表单尚有失焦未提交内容时，显式离开需先提交，失败留在当前页并提示，不能借搜索跳页丢输入。

### 5.3 保存、取消与恢复默认

模型配置仍走 useAiStore 的原保存/凭据路径，数据目录走 fileio/native，通用排版走 ui；不把所有设置统一塞入插件 applyPref。复制供应商不复制密钥，密钥不回显/不进备份的现有行为继续保留。

隐现「恢复默认」明确恢复字体、字号、纸面装帧、theme 和顶栏设置，沿用桌面默认值；不切换皮肤，不重置 AI/知识库、作品、存储位置。需把插件只涵盖四项的快照/撤销扩至这组桌面外观项，并保留纸面保存失败反馈。

迁移/删除/恢复等沿用既有确认流程，路径选择或文件保存取消不显示成功，不提前切换当前路径。迁移启动后显示正在迁移、即将重启并阻止重复操作；失败留在设置中可重试。所有验证使用隔离测试数据。

## 6. 专项验收（必须随主计划落实）

| 编号 | 场景 | 通过标准 |
|---|---|---|
| D-01 | 1080px 主窗各模块及大纲专用顶栏 | 入梦、浅眠、当前模块独立窗均可发现且不遮挡，操作语义一致 |
| D-02 | 六种常规拆窗、重复打开与锁迁移 | 正确实体/模块、单实例聚焦、来源窗准确只读，关闭恢复；窗口本地切 tab 不绕过锁 |
| D-03 | 保存失败、普通关闭、系统关闭 | 不关闭含未提交内容的面板、不释放编辑权；错误可见可重试 |
| D-04 | AI 停靠/覆盖/已拆出 | 不双开会话、不挤没正文；收起/换肤不丢对话或中止生成；浅眠聚焦已拆窗 |
