## 6. 保留差异（逐条写清为什么）

1. **剧场节点高度不等于 `min-height`**：设计稿 `min-height:84px`（选中 103）是下限，内容（portrait 34 + h3 17/1.5 + small 11 + padding 13/11 + 间距）会把实际高度撑到 **111 / 116**。判据因此取「width 从严 + height 守下限」，实测值写进证据。
2. **窄档整块 pane 的上沿与设计稿差约 50px**：设计 760 档 `y=166`（其顶栏 84 + 浮动导航行 82）；插件宿主窄档顶栏是 56 且没有那行导航，实测 `y=116 = 56 + 48(工具条) + 12(留白)`。留白 12 与工具条 48 与设计一致，差额 100% 来自宿主外壳。
3. **B 群像卡册不做**：设计稿 README 已把它排除在总稿之外，导航里没有入口。
4. **不引入草稿层**：插件人物编辑是即时落库（`work.updateCharacter`），设计稿是 `drafts` + 保存/取消。实现为「编辑态 + 完成/取消（取消=退出编辑态，已写库内容不回滚）」。若要真草稿需另开一轮（涉及草稿表与冲突合并）。
5. **图标替换**：`OIcon` 没有 `people`/`collapse` 字形，名录头用 `user`、收起键用 `arrow-left/right`。
6. **1100–1320 的 `--left:220/--right:280` 不实现**：原型把栏宽内联写在 `#workspace` 上（`app.mjs:55`），媒体查询里的这对值是**死规则**；`report.json` 的 1280 实测也是 248/304，反证不生效。
7. **右列页脚保留「N 条关系 · M 条设定」**：设计稿 `.pane-foot>span` 是通用槽位（卷宗页脚用它显示「作品 / 人名」），人物右列用它显示计数；设计稿那一屏恰好没有 span，属可选内容，不视为差异。
8. **`dsh.css` 节号从 5 跳到 7**：删除第 6 节（人物旧皮肤）后保留空号，是为了守住「`diff` 零新增」的硬约束；重编号必然产生新增行。
