## 2. 结构表：三视图 × 列

外壳 `.lore-shell` 是 grid，**列间距恒为 0**（实测 `columnGap=0px`），16px 的呼吸由独立的
`.lore-divider` 网格列承担。列宽由 store 写成 `--lore-nav-w / --lore-list-w / --lore-detail-w`
三个内联变量，算法在 `lore-layout.js`（纯函数，可单测）。

| 视图 | 网格模板（`data-view`） | nav | 分隔 | list | 分隔 | main | 分隔 | detail |

| **A 条目编写** `write` | nav 16 main | 220（可收 **40** 细轨「世界设定」） | 16（`role=separator`，可拖 / 双击 / 键盘） | — | — | `minmax(480px,1fr)`（1440 实测 1091） | — | — |

页头住在 **main pane 内**（`.lore-pane[data-pane=main] > .lore-head`，高 / min-height 105）：

| 视图 | `h1.lore-h1` | `.lore-meta` 概要行 | 右簇 |
| --- | --- | --- | --- |
| A（scope=`set`） | 当前集名（种子「地理与场所」） | 有：「设定集 · N 条目 · M 条关系」 | `.lore-scope` 范围胶囊 + 「新建条目」 |
| A（scope=`all`） | 「全部设定」 | 有：「N 个设定集 · …」 | 同上（胶囊变「当前设定集」） |
| B | 「设定详情」 | **无** | 只有三视图切换器 |
| C | 「视觉导图」 | **无** | 只有三视图切换器 |

**范围切换**（`ui.loreScope`）：`set` 只渲染当前集且**不画组头**（`.lore-set-head` = 0）；
`all` 每集一个组头（种子 2 集 → 2 个 `.lore-set-head`，实测 `["地理与场所","组织与势力"]`）。
组头吸顶：`all` 下滚 160px 后 `head.top=280 / editor.top=280`（±1.5px 判定通过）。

**窄档（≤1099）**：三列网格退化为单列 flex，`.lore-divider` 与细轨一律不出现；nav 脱流成抽屉
（`position:absolute`，宽 270、左 16、上 8、下 20，`z-index:31`），点面包屑里的 `.lore-crumb-nav`
（「世界设定」）打开、点 `.lore-scrim`（`z-index:30`）或按 Esc 关闭；list / detail 与 main 由
`.lore-shell[data-screen]` 两屏互斥（`main` 默认 / `list` B 进入时 / `insp` C 的摘要）；
三处 `.lore-mobile-back` 只在窄档 `inline-flex`（B 阅读区→条目列表、C 导图→摘要、C 摘要→导图）。

**宽度预算**（`lore-layout.js`）：`available = innerWidth - 56`，`budget = available - (write?16:32) - 480`，
nav 取 `min(navWidth, budget - other)`，side 再减 nav，各列不小于 40 —— 即「主区永远先拿到 480」。
1120 时 map 视图的 detail 被压到 332（默认 348），主区正好 480；这是设计稿的取舍，单测有 3 条钉它。

## 8. 双层 padding 修复（2026-11-06 定向补验收）

### 8.1 现象

设定工作区的**有效留白是 56 / 48，而设计稿是 28 / 24** —— 每个方向都多出一倍。
1440 档截图 `.tmp-verify-app/lore-spec-1440-A.png`（修复前那张）里导航卡左沿 `x≈57`、上沿 `y≈131`，
而设计稿应为 `≈28 / ≈108`。功能判据当时全绿，肉眼看只是「整体往里缩了一点」，所以在第一轮验收里漏过去了。

### 8.2 根因

两层各自给了同一份留白：

| 层 | 规则 | 值 |
| --- | --- | --- |
| 主题层 `app/src/styles/themes.css` | `.lore-shell { padding: 24px 28px 30px }`（宽档）、`@media(max-width:1099px)` 里 `12px 20px 20px`、`@media(max-width:559px)` 里 `7px 12px 12px` | 28 / 24（宽档） |
| 皮肤层 `app/plugin/dsh/dsh.css`（修复前） | `body[data-skin=dsh] .workbench-shell[data-module=lore] .wb-body { padding: 24px 28px 30px }` 与 `.panel-host[data-module=lore] .panel-body { padding: 24px 28px 30px }`，窄档另有两处 `12px 20px 20px` / `7px 12px 12px` | 28 / 24（宽档） |

两层都是企业级真值来源（主题层给桌面构建、皮肤层给插件构建），叠起来就是 56 / 48。
单纯删掉其中一层又不安全：只删主题层，桌面构建就没留白了。

### 8.3 修法

留白**只归主题层的 `.lore-shell` 一层**（两种构建都拿得到它），皮肤层不再给
`.wb-body` / `.panel-body` / `.lore-shell` 任何 padding，只保留 `gap: 0`（列间距本来就靠 16px 分隔列）：

```css
/* app/plugin/dsh/dsh.css:2153-2165（修复后） */
/* ⚠ 工作区留白（宽 24/28/30、≤1099 12/20/20、≤559 7/12/12）只由 themes.css 的 .lore-shell 那一层提供：
   插件构建与桌面构建都拿得到它。本层不要再给 .wb-body / .panel-body / .lore-shell 加 padding，
   也不要把 .lore-shell 的 padding 清零——那会叠加或抵消，1440 实机曾因此多出 28/24。 */
body[data-skin=dsh] .workbench-shell[data-module=lore] .wb-body { gap: 0; }
body[data-skin=dsh] .panel-host[data-module=lore] .panel-body { gap: 0; }
```

（窄档的两处 `.wb-body/.panel-body` padding 也一并删掉，只留 `.lore-shell` 的 `12/20/20` 与 `7/12/12`。）

### 8.4 修复后实测

| 量 | 期望 | 实测 | 偏差 |
| --- | --- | --- | --- |
| `.lore-pane[data-pane=nav]` 的 `left`（1440） | 28 | **29** | +1（±1 内） |
| `nav.top - .app-topbar` 底部（1440，顶栏 84） | 24 | **24**（nav.top=108 / topbarBottom=84） | 0 |
| `.wb-body` 的 `padding-left` / `padding-top` | 0 | **0px / 0px** | 0 |
| `.lore-shell` 的 `padding-left`（留白唯一来源） | 28 | **28px** | 0 |
| 抽屉 `left`（760，`.pane.nav{left:16px}`） | 16 | **17** | +1（±1 内） |
| 1440 主区宽（网格 `minmax(480px,1fr)`） | — | **1147**（修复前 1091，差值正好是两层留白多出的 56） | — |

残留的 +1：`.lore-shell` 的某个祖先把内容盒推到视口 `x=1`，本次**未定位到具体规则**
（`html / body / #app / .app-root / .wb-body` 都已确认没有 border 或 padding），±1 内通过；
截图上左沿就是 29px，可直接复核。若后续要精确到 28，属 app 侧样式问题，需要另开修复单。

### 8.5 判据盲区：为什么第一轮没抓到

第一轮的 `compare-lore` 判的是 **`.lore-shell` 的 computed padding**（24/28/30）。
这条判据在两层的世界里**永远是绿的**：`.lore-shell` 自己的 padding 一直是 28，
内缩发生在**外面那一层**（`.wb-body`），而 computed style 是逐元素读的，
没有任何一条判据去看「元素实际在视口里的位置」。

改法：判据从「声明的 padding」改成「**有效偏移**」——直接量
`.lore-pane[data-pane=nav].getBoundingClientRect().left` 与
`nav.top - .app-topbar.bottom`，并额外钉一条「外层 `.wb-body` 的 `padding-left == 0px`」，
让「再叠一层」这件事一出现就判红。

## 13. 第五轮：设定树圆点错位

### 13.1 现象（用户截图）

折叠一个分支后，行首那颗圆点整体**向左跳**：父行与子行的圆点不在一条竖线上，折叠态与展开态各歪一段；
再展开时圆点又跳回去，同层级之间也参差不齐。拖动柄（行首握把）与圆点之间同样错位。

### 13.2 根因（三套样式叠在一起，行首一组没有确定性几何）

| 来源 | 写了什么 | 为什么会错位 |
| --- | --- | --- |
| dsh 层折叠态 | `.ob-bullet::after{content:'▸'}` 用伪元素画三角，`.ob-bullet::before` 又用写死 `margin:-2.5px/-3.5px` 画圆点 | 展开态与折叠态走两套盒模型：折叠时 `::after` 参与排版把宽度挤走，圆点被顶偏；写死 margin 不随字号/行高变，一改就歪 |
| 并发样式 `lore-free-tree.css`（未被 git 跟踪，另一路产出，`LoreWorkspace.vue:9` 引入） | `.lore-shell[data-view] .lore-main .ob-row .ob-bullet::after{content:''}` 用 ::after 画圆点，`.ob-bullet{width:21px;height:28px}` | 与 dsh 层互相覆盖，两套宽高/伪元素交替生效，折叠切换时命中的规则不一样 |
| 折叠键 `.ob-fold-toggle` | 叶子行用 `display:none` 收掉 | 叶子行少了一个盒子，后面的圆点整体左移 → 与父行不在一条竖线上 |

### 13.3 修法（只动两层 CSS：`themes.css` + `dsh.css`，用特异性压过并发样式）

1. `.ob-fold-toggle` 固定 **16×27**；叶子行 `.empty` 改 `visibility:hidden`（保留占位，不再 `display:none`）。
2. `.ob-bullet` 恒 **21×27**，圆点只由 `::before` 以 `translate(-50%,-50%)` 绝对居中，`::after{content:none}`；
   折叠态不再画 ▸（三角归 `.ob-fold-toggle` 的 caret 的 `rotate`），因而折叠与展开共用同一套盒模型。
3. `.ob-drag-handle` 绝对定位 `left: calc(min(var(--depth)*22px,154px) + 2px)`，跟层级走而不是跟盒子流走。
4. 特异性：我们的规则用 `html .workbench-shell[data-module=lore] .lore-main .lore-surface .ob-row > …`，
   即 **(0,6,1)/(0,6,2)**，压过 `lore-free-tree.css` 最高的 `(0,6,0)`（`.lore-shell[data-view] .lore-main .ob-row .ob-bullet.has-children::after`），不赌文件加载顺序。

### 13.4 判据（lore-1280 场景，真机 5 条）

| # | 判据 | 期望 |
| --- | --- | --- |
| 1 | 折叠前后同一颗圆点不动 | `.ob-bullet` 的 `rect.left` / `rect.top` 差 ≤ **0.5px** |
| 2 | 再展开复位不跑位 | 相对首次展开的 `rect.left`/`rect.top` 差 ≤ **0.5px** |
| 3 | 同层叶子与父行对齐 | 同一 `data-depth` 下，父行与叶子行 `.ob-bullet` 的 `rect.left` 差 ≤ **0.5px**（数据里没有同层叶子时用 `store.mubuAdd` 在同一父级下补一颗） |
| 4 | 不再有 ▸ 伪元素 | 每颗 `.ob-bullet` 的 `getComputedStyle(el,'::after').content` ∈ {none, normal} |
| 5 | 叶子行折叠键仍占位 | 叶子行的 `.ob-fold-toggle`：`visibility === 'hidden'` 且 `offsetWidth ≥ 12` |

### 13.7 残留说明（谁还没解决、为什么）

1. **未跟踪样式仍是并发来源**：`app/src/styles/lore-free-tree.css` 不在 git 里、由另一路产出，本轮没有删它、也不改它，

2. **本轮同时暴露一个真实回归（app 源码，未修，按约定回报）**：
