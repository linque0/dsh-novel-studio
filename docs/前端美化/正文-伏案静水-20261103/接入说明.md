## 二、与书架设计稿的关系

**继承**（逐值一致）：液态玻璃三段渐变 + 1px `rgb(255 255 255/.18)` 描边 + `blur(18px) saturate(1.5)` + 内高光 + `0 26px 60px rgb(0 0 0/.5)`；118deg 高光伪元素；朱记 `#c0483a` / `#ff9384`；宋体标题 + 9px/.32em 拉丁小字对位；主曲线 `cubic-bezier(.22,.61,.36,1)`。

**刻意不同**：
1. 背景不是同一幅 mesh：正文页是「静水」墨晕（+ 灯下 / 远山两备选），书架仍原稿。
2. 正文排宋体 17.5 / 1.95 / 首行缩进 2em —— 宿主 `--dsh-content-font-size` 只影响 UI 文字，正文另留一档（`--ls-fs`）。
3. 三栏「浮起」：列宽度量（252 / ≤36em / 280）与塌陷规则不变，只换容器的长法。

## 三、落地记录（2026-11-03，已进 app/，`npm run verify:app` **64/64**）

落地分五路完成：`latent-studio.css`（1151 行）· `studio-gl.js` · `Workbench.vue`（背板挂载 + `latent-studio` 命名空间 + `tinyMq` 窄栏收起 + 抽屉宽度三档）· `EditorToolbar.vue`（17 个 `data-act`）· `ChapterTree.vue`（`data-kind`）· `verify-app.mjs`（+8 条断言）。

**真机上与设计稿不同、必须记住的四件事**：

1. **批注栏根类叫 `.right-panel`**（不是 `.rp-panel`）；章节栏是 `#writing-directory.side-panel`，**宽度来自行内 `ui.sideWidth`**（CSS 覆盖不了，≤1179 由宿主 `min(sideWidth,168)` 决定）。皮肤因此只做材质与内部排版，不碰宽度。
2. **章节树是 naive-ui `NTree`**：卷/章在 DOM 上无区分属性，已给 `render-label` 的 span 补 `data-kind`。注意 `data-kind` 落在**文本 span 本体**，选择器要直接命中 `[data-kind='volume']`；写成后代方向会静默失效。
3. **「更多格式 ⌄」下拉被 naive-ui teleport 到 `body`**，落在 `.latent-studio` 之外，本皮肤管不到（属宿主浮层主题）。
4. **≤560 要宿主配合**：`dirVisible` 为真时细轨 `.ol-side-rail` 不渲染，所以需要 `Workbench.vue` 在进入 ≤560 时把 `ui.sidePanelOpen` 收起一次；抽屉宽度用 `tinyDrawer() ? min(280, sideWidth) : …` 单独放行。

**一条教训**：第一次落地 `verify:app` 报 **58/58 全绿**，截图却是**整页空屏**——`<canvas class="st-backdrop">` 没有 CSS 约束时按属性尺寸（约 1600×1000）参与流式布局，把整页顶出视口；元素仍有 layout，于是行宽 / 对比度 / 栏宽全部照绿。补 `.st-backdrop-wrap{position:absolute;inset:0}` + `canvas{width/height:100%}` 才修好。为此给验收加了两条「能抓住看不见」的断言：`背板铺满视口`（上下界都判）与 `内容在视口内`。**断言只证明写下的那几句成立，画面必须自己看。**

## 六、响应式重排（2026-11-03 第二轮，针对真机 695px 的挤压反馈）

**问题**：真机 DSH 右侧面板宽 695px，三栏把正文挤到一行 10 个汉字；工具栏换行；章节行标题截断而字数折行；右缘批注 rail 点了没反应。

**新档位表**（按写作优先排）：

| 宽度 | 章节栏 | 批注栏 | 正文列实测 |
|---|---|---|---|
| ≥1180 | 252 常驻 | 280 常驻（三栏） | 513px |
| 560–1179 | 168 常驻 | 覆盖式抽屉（rail 脱流 20px） | 695→**377** / 760→434 / 1000→**542** |
| ≤560 | 覆盖式抽屉（rail 脱流） | 抽屉 | 380→**322** |

关键手法：`--ls-gutter: clamp(12px,3vw,96px)`、`--ls-pad-x: clamp(18px,4.4vw,64px)` 让留白随宽度收缩；工具栏任何宽度都 `nowrap + overflow-x:auto + 右缘 mask`；章节行 `__text` 省略号 + `.chapter-count` `nowrap`；两根细轨 `position:absolute` 脱流（否则 20px + gap 直接从正文身上挖走 36px）。

**这一轮抓到的三个真 bug（都不是肉眼能看出的）**：
1. 「批注栏常驻 280px」的门槛错画在 900 —— 结果 **900 档比 695 还挤**（正文列 282 vs 397）。已抬到 1180。
2. 让批注栏 `<1180` 默认收起后，**右缘 rail 在流里**，吃掉正文 36px（695: 377→341）。rail 已脱流。
3. `ui.rightPanelOpen` 默认 true + 脱流覆盖抽屉 ⇒ **一进面板批注栏就盖住正文**。已由 `Workbench.vue` 的 `collapseNotesOnWide` 在 ≤1179 收起一次。

**验收扩到 8 场景**（`shelf 380/760/1280` + `chapters 380/695/760/1000/1280`），`chapters@695` 是用户真机宽度、`chapters@1000` 守 1180 那条边界；`正文列够宽` 按档位分下界（≥1180→440 / ≤560→280 / 其余→360）对**每一档**生效。最终 `103/103` 全绿。

**教训**：只在 380/760/1280 三个「漂亮档位」上测，恰好漏掉真实使用宽度（695）。区间内的档位必须抽样，且每个档位都要有一条能量化「正文还剩多宽」的断言。

## 七、第三轮：吃掉留白 + 章节名滚动播放 + 收起键对齐（2026-11-03）

用户反馈（真机 695 与 1041 两档截图）：「妥善利用空间，取消和正文间的空隙」「显示不全的章节名可以继续滚动播放」「正文左右不用留空，完全利用整块空间」「收起章节栏与批注栏的方式对齐」。

**落地**：

| 需求 | 做法 | 实测 |
|---|---|---|
| 吃掉栏间空隙 | `≤1179` 的 `.wb-body` `gap:0` + 左右外距 0；`--ls-gutter:0` | 695 稿纸/中心栏 = **0.996** |
| 正文吃满 | `--ls-col` 由 36em 提到 **44em**（770px）；内边距用 `max(padX,(稿纸−min(44em,稿纸))/2)` 精确居中 | 1000 档 **0.955**（改前 0.782） |
| 窄栏名不被切 | 名字 `text-overflow:clip` + 悬停 `st-marquee`（主位移在 `text-indent`，纯 `translateX` 会把裁剪盒一起搬走、尾巴永远看不见）；字数固定右端 | 695 溢出实测 `scrollW 209 / clientW 64` |
| 收起键对齐 | 删掉底部 `.side-foot`，在 `.side-head` 加 `.side-fold`（`position:absolute` 钉右，因为 `.side-head > *{margin-left:0}` 会吃掉 `margin-left:auto`），与 `.rp-fold` 共用 22×22 一套 | 1280 实测 `章节键=22x22 批注键=22x22` |

**这轮踩的坑（都写进断言了）**：
1. 留白归零后，右缘那根 `position:absolute` 的 `.rp-rail` **直接压在稿纸上**，正文最后一个汉字被切半个（「毛」不见）、「历史」被切。修法：`≤1179` 给 `.wb-body` 留 `padding-right:24px`（左轨在 `≤560` 留 24px），稿纸右缘与 rail 左缘相切（实测差 1px）。新增断言 `正文右缘/左缘不被细轨覆盖` 守它。
2. `正文吃掉留白` 第一次跑出来是 `center=0 比例=-1`——Workbench 里有**两个** `.center-pane`（拆窗占位那个默认隐藏），`querySelector` 拿到隐藏的。改成挑第一个 `width>0` 的。
3. `章节名滚动播放` 一开始是假红：验证种子标题只有「第1章」，天然不溢出。改成「未溢出则跳过」+ 种子里放一个长标题（`第一章 · 初雪的钟声从港口漫上来`），让真溢出这条路在真机上被走到。

**唯一一处被放宽的旧断言**：`正文行宽<=36em` → `<=44em`（理由已写进 `verify-app.mjs:258-261` 注释：用户要求吃满空间，44em×17.5px≈770px≈45 汉字/行仍在可读区间）。其余阈值一个没动。

**已知边界**：44em 上界意味着 1920 这一档稿纸仍封 770px（比例 0.58），验收不测该档；若将来要测，`正文吃掉留白` 需要按「稿纸 = min(44em, center)」另立口径而不是固定 0.92。

## 八、第四轮：章节行贴左 + 自动滚动 + 眉标改版（2026-11-03，`130/130`）

| 需求 | 落地 | 实测 |
|---|---|---|
| 章节名向左对齐、用上左侧空间 | 干掉 `.n-tree-node-indent`，`.n-tree-node-switcher` 24px→**10px**，content padding/gap 归零 | 名字 left − 栏 left = **11px**（改前 27） |
| 过长章名自动滚动 | `ChapterTree` 新增溢出检测（`ResizeObserver` 盯 `.side-list`，溢出才加 `.is-marquee`），CSS 动画挂该类 | 长标题 `animationName=st-marquee / running`，**短标题不带类** |
| 章名不压字数 | 三层锁死：content `display:flex`、`__text` `flex:1 1 auto + overflow:hidden`、内层 span `display:block + position:static` | 文本 right ≤ 字数 left（差 0） |
| 眉标按参考图改版 | `EditorPane` 新增 `.ed-latin`（`CHAPTER ${LATIN_ORDINALS}`）/`.ed-rule`(42px)/`.ed-hairline`/`.ed-words`；顺序＝[状态][历史]→细线→字数 | `CHAPTER ONE` / 42px / 315–480px / 字数 right 差 **0** |

**关键取舍**：
1. 滚动只用 CSS 做不到「仅溢出时播」，所以由 `ChapterTree` 量块级裁剪盒后打 `.is-marquee` 类；短名字不挂类，避免「所有章名一起抖」。
2. 动画的主位移用 `text-indent`（不是纯 `transform`）——名字节点自身是裁剪盒，纯平移会把裁剪框一起搬走、尾巴永远看不见。
3. `switcher` 收到 10px 而不是 12px：栏自身有 1px 描边，12+1=13 会刚好超出 ≤12 的目标，而那条描边是设计稿的边不能去。
4. `NSelect` **没有 `quaternary` 这个 prop**（那是 NButton 的），模板侧没有为了「弱化」去写假属性，弱化交给 `.ed-head-foot` 的字号/色继承。

**这一轮三次「全绿但图上不对」**（都已补成断言）：
1. `正文吃掉留白` 量到 `center=0`——Workbench 里有两个 `.center-pane`，`querySelector` 拿的是拆窗占位那个隐藏的。
2. `章节名滚动播放` 假红——种子标题太短天然不溢出，改成「未溢出则跳过」+ 种子里放长标题。
3. `章节名压字数`——128/128 全绿却肉眼可见重叠，新增 `文本 rect.right ≤ 字数 rect.left + 1` 才把它钉住。

**仍未做**：稿纸与背景的分离度、空态、抽屉接真实数据；章节栏顶部第一个按钮（＋卷）在 695 档偏暗、卷头「未分卷」的 caret 贴边被裁一点点。

## 九、第五轮：章节栏浮层化 + 稿纸暗牌 + 底部药丸（2026-11-03，`138/138`）

| 需求 | 落地 | 实测 |
|---|---|---|
| 章节栏和批注栏一样「浮在正文上、省空间」 | `.side-panel` 在**任何宽度**都是 `position:absolute`（280px、`z-index:30`、无遮罩）；`Workbench` 挂载即收一次；细轨全档位可用 | 开栏时正文宽度 **+22px**（细轨让出的车道被收回），`position=absolute` |
| 写作区回到设计稿观感 | `.rich-host` 变暗牌：`#0f1115` + 150deg 渐变 + 1px 白描边 + 双层内阴影 + 投影 + 圆角 24 | `alpha=1`、WCAG 亮度 **0.006** |
| 新建章/卷换成设计稿药丸 | `ChapterTree` 把「＋卷/＋章」移到底部 `.side-foot`，文案「＋ 新建章」「新建卷」，沿用 `addCh`/`addVol` | 底部两颗按钮在列表下方 |

**这轮改了断言口径（都已写进注释）**：
1. `侧栏 252 / 168` **作废**——章节栏不再占列宽，改成 `章节栏默认收起`（`.side-panel` 不存在 + `.ol-side-rail` 存在）。
2. `两种收起方式对齐` 删掉「`.side-foot` 不可见」那半——`.side-foot` 现在是新建按钮的家，**必须可见**。
3. `章节栏是浮层且不占列宽` 的判据方向改对：从「开合后宽度差 ≤2」改成「**打开后不得比打开前窄超过 2px**」（开栏会收回细轨车道，正文反而变宽 `+22px`）。
4. `正文吃掉留白` 分档：`≤560 → 0.85`、`560–1179 → 0.78`、`≥1180 → 跳过`。560–1179 那档算过：1000 时 `center≈974`、稿纸 `min(44em,center)=770` ⇒ 上限比例 **0.791**，阈值 0.80 数学上不可达；0.78 的含义是「除 44em 可读性上限造成的留白外，不允许再有额外空隙」。

**教训（第五次「全绿但图不对」的同类）**：断言被旧布局的前提绑住时，改需求等于同时改断言——这一轮 10 条红里有 8 条是「面板默认不渲染」导致的假红，1 条是我把判据方向写反（开栏反而更宽），1 条是阈值定在数学不可达处。作废与改判都必须写注释，否则下一个人会当成漂移改回去。

**同一个坑的第三次现身**：章节栏从「列」变成「抽屉」后，①≤560 的抽屉宽度被行内 168 卡住 ②细轨在流里吃掉 36px ③这次又是行内 168。三次都是「宿主按旧布局给的尺寸/占位」与「新布局假定」不一致，且**都是断言没量那个量**才漏过去的。
